*Programming the MEGA65* by Craig Taylor (@CTalkobt) is a free online book, published as a static GitHub Pages site. It is modeled chapter-for-chapter on Raeto Colin West's *Programming the Commodore 64*: the machine and BASIC 65 first, then 45GS02 machine language, then graphics, sound, storage and peripherals, across 17 chapters plus Appendices A–G. It fills a gap the official books leave open: a single narrative, *teaching-order* programming text that explains why things work and shows full BASIC and assembly listings, where the official MEGA65 Book is a reference compendium. **Treat it as a secondary source, though.** The author's repo describes it as "my attempt at using AI to generate the equivalent of a Programming the Mega65 book." It was first published on 2026-10-04, and its changelog records dozens of factual corrections in its first week. Use it to learn and orient, and verify any register, bit or ROM-address claim against [[MEGA65-mega65-user-guide]] before relying on it.

## What it does

The book teaches MEGA65-mode programming from first principles to the hardware. Chapter 1 frames the MEGA65 as "three computers in one" (MEGA65 / BASIC 65, C65 / BASIC 10 with the original ROM, and C64 / BASIC 2), and the book covers the first while using the other two where they help. It notes that the "C64 for MEGA65" core is a different machine that the book doesn't cover. Readers new to programming are directed to Chapters 2–4; experienced 6502 programmers can jump to Chapter 5 and use Chapter 3 as a reference. Chapters 5, 10 and 11 are the reference backbone that later chapters rely on.

## Key features

- **Inline citations to the official book.** Technical claims are cited as "(MEGA65 Book, p. X-NN)" against the August 2025 edition of the MEGA65 Book (the Complete Compendium). Where the machine has changed since then, the newer source is cited instead, such as the ROM change log, mega65-core source files like `gs4510.vhdl`, or merged core pull requests. This makes spot-checking against [[MEGA65-mega65-user-guide]] straightforward.
- **Version-aware.** Ch1 states that the book was checked against ROM 920422 and the mega65-core development source as of September 2026. It names stable package v0.97 (April 2025, ROM 920413) as the latest stable release, and it tags features newer than stable with the ROM that added them: KERNAL CURSOR (920415), RESET_RUN (920416), VERSIONQ (920417), SYSFLAGS naming (920418), and SPRITE SYS R (920415). Some passages are explicitly marked "development cores," and Ch11 explains how a program detects its ROM, core and Hypervisor version.
- **Board-revision notes.** Revision differences are called out where they matter to programmers. Examples include audio output on older boards, R3A (2022) and R6 (2024) production attributed to the MEGA65 Book, and the R4+ real-time clock (one queued write at a time, 16 bytes of battery-backed RAM).
- **Worked code in both BASIC and assembly.** One example is the Ch8 speed control: `LDA #$41 / STA $00` forces 40.5 MHz, but the shortcut silently does nothing if MAP covers `$0000–$1FFF` or the base page register B is non-zero. Writing `$D031` to change speed is a VIC-IV "hot register" write that can undo a program's VIC-IV screen setup unless HOTREG (`$D05D` bit 7) is cleared.
- **Assembler conventions.** `;` comments, `.byte`/`.word`, and `[zp],Z` for flat addressing. The book notes the KickAssembler differences (`//` comments, `((zp)),z`).
- **Public changelog.** `changelog.html` lists every reader-visible change by date. It's a useful record of what the AI-assisted first draft got wrong. The 2026-10-11 entry includes corrections to `$D030` bits, colour RAM size (32KB on every model), Ch10 flag behaviour of PHW/BIT/STQ, the R4+ RTC, and the removal of "unsupported" claims such as an `ADDQ` mnemonic.

## Architecture

The site is plain static HTML with no build system, tests or linter. `index.html` is a hand-written table of contents. Each `chNN-<slug>.html` chapter and `appendices.html` is a standalone pandoc-generated HTML5 page sharing one `style.css`, and `changelog.html` lists reader-visible changes. The pandoc Markdown source is **not** in the repo, so edits go directly into the HTML. The only CI is a lychee link-check workflow (internal links, `#anchor` fragments, external links) run on push, on PRs and weekly. The repo's `CLAUDE.md` sets the editing conventions an AI agent must follow: chapter nav bars, an "Updated" date on changed chapters, inline MEGA65 Book citations, code in `<pre><code>`, a changelog entry per content change, and version tagging for features (../../raw/github/CTalkobt-Programming_The_Mega-65.md).

```
trb $d054       ; VFAST off

```

## When to use

- **Learning path after the Welcome Guide.** It's a continuous, West-style programming course, good for someone moving from BASIC 65 toward machine language who wants explanation rather than a register dump. It complements [[dansanderson.com]]'s Welcome Guide and Digest articles.
- **Orientation before a spec lookup.** Use it to find *which* mechanism applies (MAP, flat `[zp],Z` addressing or DMA; GOTOX/RRB layering; audio DMA versus SID) and the gotchas around it. Then confirm exact registers and bits in the official books.
- **Not as an authority.** It is an AI-assisted secondary source with heavy early correction churn, so never cite it as the final word on a register, bit, cycle count or ROM address. Its "MEGA65 Book, p. X" citations make verification fast.
